## THE LABELS

Each analysis gives its trial one label. A label is a claim from that analysis, not a verified fact.

* GOOD_SUCCESS — the agent solved the task fairly. The task is good.
* GOOD_FAILURE — the agent failed a fair task. The task is good.
* BAD_SUCCESS — the agent passed without solving the task. The task has a problem.
* BAD_FAILURE — a task problem caused the failure, or the task leaked hidden files. The task has a problem.
* HARNESS_ERROR — the infrastructure broke the run, so the run says nothing about the task. One exception: the subtype `hidden_file_leak` means the task exposed hidden files, and that is a task problem.

## STEP 1: LOOK FOR AN IMMEDIATE REJECTION

Four kinds of evidence reject the task on their own. Look for them first. If you find one, reject the task. Good results from the other trials do not cancel it.

* A used leak. A trial read the hidden tests, the solution, or other files the task must keep hidden (subtype `hidden_file_leak`, `test_inspection`, `oracle_copying`, or `unintended_access`).
* A found leak. A `must_fix` finding with the dimension `info_leakage`, from the static quality check or from a trial. The finding counts even if no trial used the leak.
* Weak tests. A trial measured that the tests also pass work that does not solve the task. Example: the untouched base model already scores above the pass threshold. Weak tests make every pass meaningless, including the ones labeled GOOD_SUCCESS.
* A failed baseline. The nop baseline changes nothing, so if it passed, the task was already solved. The oracle baseline applies the reference solution, so if it failed, the reference solution is broken.

## STEP 2: JUDGE THE REST

If step 1 found nothing, the remaining evidence is opinion — claims like "the instruction is unclear" or "the tests are too strict". One trial's opinion can simply be wrong. Trust an opinion only when most trials agree on it. Harness errors say nothing, so leave them out when you decide what "most trials" means.

Three rules:

1. A difficult task is not a bad task. A benchmark works best when only 10-40% of trials pass, so failures are expected.
2. One fair success proves the task can be solved.
3. When a trial claims the instruction is missing information, check: could the agent have found that information in the code? If yes, ignore the claim.

The decision: reject if most trials show the same task problem, with clear evidence. Accept in every other case. A run where every trial fails, a mixed run, or a single BAD label — all of that is normal for a difficult task.

## STEP 3: SET THE CONFIDENCE

* An immediate rejection is high confidence. One exception: if the only evidence is a single trial claiming weak tests, and the static quality check has no matching `must_fix` `verifier` finding, use medium.
* A rejection because most trials show the same problem is high confidence.
* An accept is high confidence when the trials agree, and low when they disagree or every trial is a harness error.

## OUTPUT

Return ONLY valid JSON (no markdown, no code blocks, no explanation):

{{
  "verdict": "accept" | "reject",
  "confidence": "high" | "medium" | "low",
  "primary_issue": "the main problem" or null,
  "recommendations": ["concrete fix 1", "concrete fix 2"],
  "reasoning": "1-3 sentences about what the trials show"
}}

How to write the fields:

* Write for the task's author, who reads this once and has seen none of the analyses. Use short sentences, plain words, and no jargon.
* Wrap every code name in backticks: files, tests, functions, variables, config keys. Use no other formatting.
* `primary_issue` — null when you accept. When you reject, state the problem with a count: "3/4 trials fail on an error string the instruction never states". Start with "CRITICAL:" when a baseline failed.
* `recommendations` — at most two small suggestions when you accept. When you reject, three to five specific fixes, most common problem first, no duplicates. "Add the file path to instruction.md line 15" is a fix; "improve the instructions" is not.
* `reasoning` — what the trials showed. If you rejected immediately, name the evidence. If you disagree with a trial's label, name the trial and say why.
