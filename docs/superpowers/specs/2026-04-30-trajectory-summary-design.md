# Trajectory Summary Panel

## Problem

Long ATIF trajectories on `oddish.app/experiments/<id>?tab=trajectory` are
hard to skim. Each trial has anywhere from a handful to several hundred
steps; finding the pivotal moments today requires scrolling the accordion
in `frontend/src/components/trajectory-viewer.tsx`. There is no overview
above the per-step breakout, just a token-usage bar and a per-step
duration bar.

We want a short narrative summary plus a small set of "key moments" with
hot-ref links into the existing accordion, generated by Claude on demand.

## Goal

Render a summary block between the existing token/duration bars and the
steps accordion. Lazy-generated on first view, cached as an S3 sibling
file. Shows a 2–3 sentence prose summary plus 3–6 highlighted steps,
each linked to the corresponding accordion item via the existing
`handleStepClick` flow.

Out of scope: streaming summaries during a running trial, manual
"regenerate" controls, schema-version invalidation/backfill, frontend
tests (no test suite wired up per `frontend/README.md`).

## Decisions locked during brainstorming

| Decision | Choice |
| --- | --- |
| Trigger | Lazy on first view; cached after first generation. |
| Position | Between `TokenUsageBar`/`StepDurationBar` and the steps accordion in `trajectory-viewer.tsx`. |
| Output shape | Short prose paragraph + bulleted "key moments" list (3–6 entries). |
| Storage | S3 sibling file at `<trial_s3_prefix>/agent/trajectory_summary.json`, mirroring the existing trajectory file. |
| Input prep | Strip image content parts; truncate any text field over ~2000 chars to first 800 + last 400 with a `[...truncated N chars...]` marker. |
| Model | `claude-sonnet-4-6` via `AsyncAnthropic`, matching `_run_probe_analyzer`. |
| Failure UX | Inline error card with a "Retry" button; no auto-regenerate. |
| When summary appears | Only after the trial has finished running (terminal state). |

## Architecture

```
Frontend tab (Trajectory)
   │
   │  GET /api/trials/{id}/trajectory/summary  (Next.js route)
   ▼
Backend FastAPI (backend/api/routers/trials.py)
   │  GET /trials/{id}/trajectory/summary
   ▼
read_trial_trajectory_summary(trial)        ─── oddish/src/oddish/core/trial_io.py
   │   1. in-memory cache hit? return.
   │   2. S3 sibling file present? read, cache, return.
   │   3. else: generate via summarize_trajectory.generate(),
   │            write to S3, cache, return.
   ▼
backend/api/services/summarize_trajectory.py
   │   - load trajectory via read_trial_trajectory()
   │   - preprocess: strip images, truncate large text fields
   │   - call AsyncAnthropic with structured output (tool-use)
   │   - validate step_ids exist; drop any stale references
   │   - return TrajectorySummary dict
```

## Components to build

### Backend

**`oddish/src/oddish/core/trial_io.py`** — add a `read_trial_trajectory_summary`
/ `write_trial_trajectory_summary` pair that mirrors the existing
`read_trial_trajectory` pattern (per-key lock, in-memory cache, candidate-key
lookup). The S3 key is `<trial_s3_prefix>/agent/trajectory_summary.json`.
Local-path fallback writes to `<agent_dir>/trajectory_summary.json` for
local-dev parity.

**`backend/api/services/summarize_trajectory.py`** — new module:

- `preprocess(trajectory: dict) -> dict`: drop image content parts (replace
  with a single `{"type": "text", "text": "[image omitted]"}`); for any
  string field over `MAX_TEXT_CHARS = 2000`, replace with
  `{first_800}\n[...truncated N chars...]\n{last_400}`. Applies to
  `reasoning_content`, the values inside `tool_calls.arguments`, and
  `observation.results[].content`. Leaves small fields untouched. Pure
  function; no I/O.
- `generate(trajectory: dict) -> dict`: builds the prompt, calls
  `AsyncAnthropic` with `claude-sonnet-4-6` and a tool-use schema that
  forces the JSON output below, validates `step_id`s exist in the source
  trajectory, drops any stale ones, returns the persistable dict.

**`backend/api/routers/trials.py`** — new endpoint, matching the
existing `get_trial_trajectory` shape:

```python
@router.get("/trials/{trial_id}/trajectory/summary")
async def get_trial_trajectory_summary(
    trial_id: str,
    auth: Annotated[AuthContext, Depends(require_auth)],
) -> dict:
    auth.require_scope(APIKeyScope.READ)
    trial = await _get_authorized_trial(trial_id, auth)
    summary = await read_trial_trajectory_summary(trial)
    if summary is None:
        raise HTTPException(404, "No trajectory available for this trial")
    return summary
```

`read_trial_trajectory_summary` does the lazy-generate-then-write flow
internally so the per-key lock guards against duplicate first-viewer
work. The router stays thin.

### Frontend

**`frontend/src/app/api/trials/[trial_id]/trajectory/summary/route.ts`** — Next.js
proxy route, identical structure to the existing
`frontend/src/app/api/trials/[trial_id]/trajectory/route.ts`.

**`frontend/src/components/trajectory-summary.tsx`** — new component:

- SWR fetch from `/api/trials/{id}/trajectory/summary` (no
  `revalidateOnFocus`).
- Loading state: muted `Card` with a spinner and "Generating summary…"
  text. Visually consistent with the existing skeleton states.
- Error state: inline error card with the message + a "Retry" button
  that calls `mutate()`.
- Loaded state: short paragraph in the card body, then a bulleted list
  of highlights. Each bullet is an interactive row (button-styled) with
  `Step N · {title}` on the first line and `{why}` muted underneath.
  Clicking the row calls a `onStepSelect(stepIndex)` prop.

**`frontend/src/components/trajectory-viewer.tsx`** — small refactor:

- Render `<TrajectorySummary trialId={trialId} onStepSelect={handleStepClick} />`
  immediately after the existing `<StepDurationBar />` (around line 819).
- Map summary `step_id` → accordion `index` before invoking
  `handleStepClick`. The mapping is `steps.findIndex(s => s.step_id === id)`.
- Hide the summary block when `trajectory` is null or `steps.length === 0`
  (nothing meaningful to summarize).

**`frontend/src/lib/types.ts`** — add the `TrajectorySummary` /
`TrajectoryHighlight` types matching the persisted JSON.

## Data shape

Persisted JSON (`trajectory_summary.json`):

```json
{
  "schema_version": "1",
  "model": "claude-sonnet-4-6",
  "generated_at": "2026-04-30T12:34:56Z",
  "summary": "The agent debugged a flaky test...",
  "highlights": [
    {
      "step_id": 12,
      "title": "Reproduces the failure locally",
      "why": "First confirmation that the bug is real and isolated."
    }
  ]
}
```

`schema_version` is a string so a future bump can be a one-off backfill
script rather than runtime invalidation logic.

## LLM prompt and structured output

System prompt (concise; full text in the implementation):

> You are summarizing a recorded agent trajectory for a developer who
> wants a quick scan before diving into the per-step view. Produce a
> 2–3 sentence summary covering what the agent set out to do and how
> it ended, then 3–6 pivotal "key moments" with their step ids.

Use Anthropic tool-use (a single `record_summary` tool with the JSON
schema above) so the model returns structured data. Reject responses
where the tool wasn't called or where the JSON fails validation; surface
those as 5xx so the frontend's retry path picks them up.

## Failure handling

| Failure | Backend behavior | Frontend behavior |
| --- | --- | --- |
| Trajectory missing entirely | 404 from summary endpoint | Component renders nothing (parent already shows the "No trajectory available" empty state). |
| LLM call raises | 502 with error message | Error card with the message + Retry button. |
| LLM returns malformed JSON / no tool call | 502 | Same retry path. |
| S3 write fails after generation | Return the generated summary anyway with a 200; log a warning. Subsequent viewers will regenerate. | Renders normally; user is unaware. |

The per-key lock means concurrent first viewers wait on the same
generation rather than firing multiple Claude calls.

## Testing

- `backend/tests/test_summarize_trajectory.py`:
  - `preprocess` strips images and truncates long fields with the
    expected marker; preserves small fields, `step_id`s, source,
    timestamps, and tool-call function names.
  - `generate` calls `AsyncAnthropic` (patched), validates step ids,
    drops stale ones, returns the expected schema. Mirrors
    `backend/tests/test_probe_analyzer.py`.
- `backend/tests/test_trial_summary_endpoint.py` (or extend the
  existing trials router test file if one exists):
  - First call generates and writes; second call returns from cache
    without re-invoking Claude.
  - 404 when no trajectory exists.
  - 502 when generation raises.
- No frontend tests (no suite wired up).

## Out of scope

- Manual "regenerate" button.
- Schema-version invalidation / backfill (tracked separately when we
  bump `schema_version`).
- Streaming summaries while a trial is still running.
- Cost accounting for the summary call (negligible vs. trial run).
